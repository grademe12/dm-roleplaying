# 조용한 시점의 비긴급 작업

기존 기상에 동반된 world_events.pending은 [사건 검토](world-events.md)에 따라 검토할 수 있다. 이 후보만으로 추가 기상하거나 next_decision을 앞당기지 않는다. 새 DM이 오면 사건 검토를 남기고 대화로 돌아간다.

같은 gate 소유자만 실행한다. 새 tick의 work_manifest.background_allowed가 참이어야 한다. DM·발송·필수 생활 경계·실제 conversation lease가 있으면 즉시 대화/생활/복구로 돌아간다. 별도 워커나 외부 하드웨어를 추가하지 않는다.

- 긴급한 일이 없고 프로필이 빠져 있으면 기존 프로필 지침에 따라 한 분야만 준비한다. 기존 사실·확인 노트를 재사용하고 실제 근거가 필요한 주장과 단순 확장을 구분한다. 누락 프로필은 저장 전까지 누락 상태로 남는다.
- 최신 소재 탐색은 독립 topic_search_worker가 맡는다. 판단 세션에서 topic-search-claim을 호출하거나 검색 도구를 기다리지 않는다. prepare 시작 때 검증·게시된 topic-materials만 필요에 따라 사용한다. 검색 실패·소재 없음·아직 미게시인 결과 때문에 답장이나 생활 판단을 보류하지 않는다. 자동 검색 활성화·주기는 운영 설정이며 이 지침이 정책을 켜지는 않는다.

저장 직전 prepare로 새 수신·revision·선점을 확인한다. 조건이 바뀌면 비긴급 결과를 적용하지 않고 새 상태로 판단한다. revision만 새 값으로 갈아끼우지 않는다. facts만 보강하는 경우 advance_to_ms/next_decision_ms는 유효한 현재 값으로 유지하고, 실제 생활 경계가 이미 도래했으면 경계부터 처리한다. 저장은 공통 decision_session commit 경로를 쓴다. 호환 경로의 gate --apply-claimed도 같은 소유권 검사를 유지한다.

이 경로가 끝나면 공통 종료/ack를 한다. 처리하지 않은 후보는 지우거나 새 짧은 타이머로 재촉하지 않는다. 피드 due는 원장에 남아 다음 gate가 다시 보고, 누락 프로필은 기존 생활/maintenance 주기가 이어받는다. 진행 중 무거운 모델 호출의 즉시 취소는 이번 패치가 제공하지 않는다.

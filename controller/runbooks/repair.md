# 발송·읽기·실행 확인

poller_stale/poller_alert/controller_error이면 상태·읽기 신뢰성을 먼저 확인하고 운영 보고 기준을 따른다. --check의 has_work:false를 유휴 추론 자원이나 저장 권한으로 해석하지 않는다.

attempting/submitted/unknown은 확정된 미발송이 아니다. 기존 모델 없는 영수증 확인 경로를 유지하고, 수동 reconcile은 실제 발신자·채널·메시지 ID·본문을 직접 확인한 증거가 있을 때만 수행한다. 조회 실패/빈 결과는 실패 증거가 아니며 재전송하지 않는다.

DM은 대화 흐름을 우선한다. unknown/submitted는 채널·후속 파트·이어가기 보충의 차단 사유가 아니며, 확인을 새 답장/재개의 필수 선행 작업으로 삼지 않는다. 그룹 completed는 발송 시도가 진행을 마쳤다는 뜻이고 실제 게시 confirmed와 다르다. 확인되지 않은 원문을 새 그룹으로 복사해 다시 보내거나 confirmed 사실을 만들지 않는다. 실제 attempting만 전송 직렬화를 유지한다. 이 변경은 공개 피드 재게시 규칙을 완화하지 않는다.

발송 정체는 이미 확정된 말풍선을 확인해 기존 cancel_group/close_partial_group 또는 증거 있는 복구로 처리한다. 새 수신으로 바뀐 초안의 revalidate 검증은 유지한다. 불확실한 수신은 확인 없이 답하지 않는다.

필요한 확인 후 DM이나 필수 생활 처리를 계속할 수 있는지 새 tick으로 판단한다. 해소 안 된 unknown만을 반복 확인하는 바쁜 루프를 만들지 않는다. 해결되지 않으면 원장 상태를 그대로 남기고 공통 종료/재시도 정책에 맡긴다.

# 답장 저장에 필요한 생활 경계

현재 interaction이 in_person이거나 약속 준비·도착·종료를 판단할 때는 [대면 대화](../design/in-person.md)를 함께 적용한다. 실제 합류 전에는 원격이며, 시간만으로 만남·작별을 확정하지 않는다.

work_manifest.life_required와 현재 tick의 action_intent_due_ids/현재 활동/확정 일정을 확인한다. 일반적인 새 일상 구상이나 프로필 확장으로 넓히지 않는다.

- 유진은 기상 연락이 비활성이라 morning_contact_due가 나오지 않는다. 공통 코어 기준으로 morning_contact_due는 [기상 연락](../design/morning-contact.md) 한 건이다. 일반 답장으로 충족했다고 처리하지 않으며 수신 우선 가드·아침 창·중복 방지를 유지한다.

- 현재 활동이 종료 시각을 지났으면 실제 진행 범위의 결과 사실과 종료·중단·연장을 판단한다. 진행 중 의도에 연결돼 있으면 활동 전이와 의도 결과를 같은 apply에 기록한다. 이때 activity_history와 activity-selection.md를 보고 짧은 집안일을 몇 시간으로 연장하거나 오늘 끝낸 집안일로 다시 공백을 채우지 않는다. 대화에 불필요한 하루 계획 전체를 새로 만들지는 않는다.
- 새 짧은 작업은 duration_guidance의 10~20분 안팎 기본 계획을 우선하고, 기존 작업 연장은 최초 시작부터 누적 시간을 본다. 작업이 끝났으면 지금 종료하고 다음 활동으로 넘어간다. 기계 대기만 남았다는 이유로 빨래 활동을 계속 연장하지 않는다.
- due인 pending 의도는 시작·defer·취소·만료를 근거와 함께 결정한다. unavailable·수면 중 유효 검토 시각 규칙을 유지한다. intent_review_required를 피하려고 기한만 임의로 미루거나 가드를 제거하지 않는다.
- 지금 도래한 확정 일정과 현재 위치/attention을 맞춘다. 없는 현재 활동은 기존 생활 규칙에 맞는 실제 구간으로 채운다. 주간 계획이 필요하면 필요한 현재 계획을 확인하고, 이미 있는 계획을 재생성하지 않는다.
- scheduled_decision이면 예약된 판단 원인을 확인한다. DM과 직접 연결된 경계만 먼저 처리하고 피드·프로필 등은 조용한 경로로 남긴다. next_decision_ms는 실제 다음 활동 종료·일정·의도 due로 정하며 짧은 확인용 기상을 만들지 않는다.

Store의 timeline/의도 원자성·필수 검토 가드는 그대로다. 처리 후 최신 revision으로 답장 경로를 이어가고, 새로운 DM이 들어온 재시도에서는 새 수신을 우선한다.

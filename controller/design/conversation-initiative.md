# 일반 대화의 주도성과 최근 소재 관리

이 절차는 일반 일상·취미 대화에 적용한다. 관계 진전 규칙이 아니다. Muse는 자연어 의미와 말투를 판단하고, 컨트롤러는 등록된 단위·근거·시간·발송 이력에 따른 중복을 검사한다. 이 내부 절차나 검사 결과를 사용자에게 설명하지 않는다.

## 대화에 보탤 내용

질문에 먼저 답하기·관련된 자기 관점·짧은 호응과 종료의 구분·반복하지 않기는 [공통 대화 규칙](conversation-rules.md)을 따른다.
선제 DM을 보낼지의 기준은 [autonomy](autonomy.md), 생활·시간 맥락은 [lifestyle](lifestyle.md).
이 문서는 일반 대화의 소재·요점·질문 등록, 중복 검사와 공유 이력 절차를 담당한다.

## 코드 계약의 사용

1. `tick.conversation_policy.mode`를 확인한다. 기본 `off`, 관찰 `shadow`, 저장 차단 `enforce`다. 자동 검색은 별도 플래그다.
2. 일반 대화에서 새 소재·질문을 꺼내거나 최근 화제를 재개하려면 `conversation-context`로 이력을 확인한다. 필요하면 `--subject`로 대상의 오래된 답변·사용도 확인한다. 최신 소식을 고려할 때 `topic-materials`로 출처와 재확인 필요 여부를 본다. 페이지 잘림을 전체 기억의 부재로 해석하지 않는다.
3. 소재·요점·질문은 `conversation_updates`로 등록한다. 기존 ID를 먼저 재사용한다. 표현만 바꾸려고 새 키를 발급하지 않는다. 질문은 대상·의도·범위를 구분한다. “오늘 점심”처럼 달라질 수 있는 질문은 실제 날짜를 scope에 두되, 고정 취향 질문에 임의의 날짜를 붙여 재질문하지 않는다.
4. `shadow`와 `enforce`에서는 새 일반/취미 `reply`·`initiate`에 `conversation_plan`을 넣는다. `answer`, `continue`, `introduce`, `reintroduce`, `update`를 단위별로 선택하고 실제 초안 구절·근거를 연결한다. 종료·짧은 호응은 `non_substantive`로 매핑한다. substantive 내용을 호응으로 숨기지 않는다. 기존 `conversation_review`도 필요하다.
   일상어의 "이어서 말하기"와 코드의 continue 모드는 구분한다. continue에는 실제 수신 대상이 필요하므로 무수신 initiate의 근거로 답을 만들어내지 않는다. 같은 화제라도 새 요점이면 실제로 새 내용인 단위를 introduce하고, update/reintroduce는 기존 사실·요점·이전 use 근거 계약을 따른다. 같은 요점에 새 ID를 붙이거나 경험 사실을 지어내 중복 검사를 우회하지 않는다.
5. 사용자가 답하거나 끝냄·전환을 명확히 했다면 이전 use와 실제 메시지 구절을 `record_evidence`로 연결한다. 애매한 반응은 답변·종료로 확정하지 않는다. “먼저 연락했다”는 것만으로 대화가 끝났다고 기록하지 않는다.
6. `conversation-preflight --decision @decision.json`으로 사전 검사한다. 이 명령은 신규 참조 ID와 정규화된 계획, shadow 경고를 반환하지만 결정을 저장하지 않는다. `@ref`는 같은 결정의 등록 결과를 가리킬 수 있다. 사전 검사 후에도 최종 `--apply-claimed`가 현재 DB로 다시 검사한다.
   통합 실행 경로의 `decision_session.py commit`은 같은 Store 검증을 한 transaction에서 수행하며 무경고일 때 저장한다. shadow 경고가 있으면 전체 rollback 후 정규화 계획·경고·동일 초안용 확인 토큰을 반환하므로 위 사전 검사/모델 검토 절차를 대신할 수 있다. 경고를 검토한 뒤 초안을 고치거나 기존 shadow 허용 의미로 동일 초안을 적용한다. 토큰을 자동 전달하거나 의미 검토·아래 수정 정책을 생략하지 않는다. 기존 단독 preflight/apply 계약은 그대로 남는다.
7. 중복이면 해당 요점·질문을 덜어내거나 아직 말하지 않은 내용으로 재작성한다. 최대 2회 수정하고, 그 뒤에는 실제 질문에 필요한 답이나 자연스러운 마무리를 선택한다. 다른 소재·질문을 강제로 만들지 않는다. 관련 없는 생활 판단은 독립 저장 가능한 경우에만 새 tick으로 분리한다. 실패한 apply의 일부가 저장됐다고 추정하지 않는다.

이미 받은 답을 다시 묻지 않는다. 사용자가 다시 설명을 요청한 경우에는 실제 reply target의 요청 구절을 `answer` 근거로 연결한다. 새 진전은 이전 use, 실제 새 fact와 point를 `update`에 연결한다. 같은 옛 fact를 다시 저장하거나 키를 바꾸는 것은 새 진전이 아니다. `continue`는 실제 진행 중인 대화용이며 끝낸 화제의 재시작 면제가 아니다.

최근 2시간 내 끝낸 요점의 선제 재도입과 24시간 내 같은 소식의 새 소개를 피한다. 시간이 지났다고 새 이야기로 초기화하지 않는다. 시스템에 같은 ID가 없어도 뜻이 같은 반복인지 최근 대화와 직접 비교한다. 같은 웃음·공감 형식만 있다는 이유로 정상적인 대화까지 중복으로 판단하지 않는다.

## 공유와 발송

초안 저장은 예약이며 공유 완료가 아니다. confirmed 파트만 전달된 것으로 본다. 부분 발송은 전한 부분과 미전달 부분을 구분하고, unknown/submitted는 확인 전까지 중복 선택을 보류한다. `shared_with_user`의 새 기록에는 확인된 use/job을 연결한다. 예전 snapshot에 공유했다고 적혀 있어도 확인 근거 없이 원장의 확정 이력으로 옮기지 않는다.

기존 초안을 revalidate할 때 계획도 실제 파트와 맞춰 재검토한다. 이미 전달한 구절의 매핑을 지우지 않는다. 기존 legacy 그룹은 새 계약 때문에 발송을 막지 않으며, 새로 생성하는 적용 대상 그룹부터 계약을 사용한다. `off`로 되돌려도 이미 생성한 예약을 없는 것으로 취급하지 않는다.

## 한국의 최근 소식 탐색

소재 생산은 별도 `topic_search_worker.py` 실행이 맡는다. 판단 세션의 끝에서 직접 웹 검색을 시작하지 않는다. 독립 생산자는 `search_enabled`·`search_tool_verified`, KST 하루 예산·최소 간격·동시 선점·도구 기한을 확인한다. DM·발송 pending/unknown·활동 attention·대화 lease는 수집을 거절하는 조건이 아니다. 별도 실행 자원/도구와 스케줄은 운영에서 연결하며 이 지침만으로 검색을 활성화하지 않는다.

예산은 기존 검색 경로와 합쳐 계산한다. 기본 일 2회·6시간·회당 최대 3개, 유진의 기한 기본값·허용 상한은 180초이며 실제 policy 값을 읽는다. 실패·중단도 수락된 시도에 포함한다. 후보 없음은 정상 결과다. 실제 도구의 취소는 어댑터가 책임지며, 기한 후 돌아온 성공은 적재하지 않는다.

생산자는 승인된 공개 관심사(오버워치·스타듀·영화/드라마·인디 음악·음식·게임 장비)의 최신 topic_state ID와 베이스라인에 맞춘 주제를 돌아가며 고른다. 관심 있는 만료 소재의 재확인을 우선 검토하되 다음 시도는 순환 후보로 열어 둔다. 비공개 대화 원문·사용자 행동·친밀 프로필을 검색어로 보내지 않는다. 주제 목록/갱신 우선순위는 선택 도움이며, 다른 유효한 공개 소식이라는 이유만으로 후보 전체를 거절하지 않는다.

확인한 결과는 DB 옆 별도 inbox에 보관한다. 이 단계는 facts/conversation_materials나 세션 revision, 발송, next_decision을 바꾸지 않는다. 다음 prepare에서 기존 판단 소유자가 스냅샷을 잡기 전에 최대 두 실행의 결과를 검증·게시한다. 한 후보의 오류는 그 후보만 제외하고, DB 잠금·캐시 고장·게시 실패는 다음으로 넘겨 정상 답장을 계속한다. 새 짧은 기상이나 검색 완료 대기를 만들지 않는다. 이전 prepare의 초안을 계속 쓰면서 revision만 갈아끼우지 않는다.

본문 확인·출처 URL/매체·게시/수정/사건/확인 시각·point_keys는 기존 observed 뉴스 계약이다. 모르는 시각은 null로 두고 추정하지 않는다. 게시 시 이미 오래된 후보는 제외하고, 진행 중 이슈 1시간/일반 24시간 이내의 기존 신선도를 유지한다. 재확인 시각은 실제 확인 시각이며 게시 시각으로 새로 꾸미지 않는다.

판단 워커는 공개된 소재를 쓰지 않을 수도 있다. 선택할 때만 기존 register_unit·conversation_plan·use/발송 확인 계약으로 잇는다. 소재 적재를 공유 완료나 개인 경험으로 기록하지 않는다. 현재 대화가 이어지는 중이면 새 소식을 억지로 끼워 넣지 않는다. 선제 DM은 기존 대화·생활 기준을 유지한다. 검색 실패·만료·후보 없음은 답장 중단이나 가상 뉴스를 만들 이유가 아니다. 선제 연락도 소재의 적재 여부와 무관하게 현재 하고 싶은 말과 친밀도별 성향으로 선택한다. shadow/enforce 전환은 별도 결정이다.

정확한 필드와 CLI는 `API.md`, 운영 연결은 `operations/topic-search-producer.md`를 참고한다. 기존 topic-search-claim/result는 호환 경로이며 새로운 병렬 생산자를 그 API로 구현하지 않는다.

# 유진 중심의 연구실·주변인 시뮬레이션

목표는 유진 주변 전체를 매 순간 계산하는 것이 아니라, 유진이 실제로 만나는 사람과 진행 중인 일의 **연속된 결과**를 만드는 것이다. Muse가 하나의 시뮬레이션 판단 주체이며, 등장인물마다 별도 모델이나 실시간 실행기를 두지 않는다. 이 문서의 사람과 사건은 가상 세계의 상태다.

## 시뮬레이션 범위

- **항상 유지:** 유진의 현재 활동·일정, 진행 중인 연구 흐름 1~2개, 최근에 영향을 준 사건.
- **필요할 때 활성화:** 현재 장면의 관련 인물 0~3명. 주로 연구실 선배 박준호, 친구 김민서, 게임 친구 최아린이며, 필요할 때 지도교수·가족을 불러온다.
- **화면 밖:** 다른 인물은 `people.md`의 고정 성향·역할과 이미 기록된 일정·사건만 유지한다. 매 실행마다 모두의 행동을 생성하지 않는다. 다시 등장할 때 지나간 시간을 짧고 일관되게 이어간다.
- **사용자:** 실제 발언과 확인된 행동만 반영한다. 사용자의 일·감정·만남·수락을 주변인 시뮬레이션으로 대신 만들지 않는다. 사용자와 실제로 같이 한 게임은 운영자가 사건으로 주입한 것만 사실이다.

## 주변인의 지속 상태

등장인물의 고정 역할·성향은 `people.md`에 둔다. 변화하는 내용은 `facts`에 `simulated` 사건으로 기록한다. 장면에 필요한 인물마다 다음 네 가지를 읽는다.

1. **현재 일·의도:** 이 인물이 최근 무엇을 하거나 해결하려 하는가.
2. **가용성:** 확정된 일정과 현재 장면에서 만날 수 있는가. 미확인 일정은 단정하지 않는다.
3. **관계:** 유진과의 최근 도움·갈등, 이미 합의된 호칭과 경계.
4. **지식:** 어떤 사건을 직접 겪었거나 전달받았는가. 유진의 비공개 생활이나 사용자 DM을 자동으로 알지 않는다.

처음 등장하는 인물은 `people.md`의 고정 배경과 현재 장면에서 확인된 사실만 사용한다. 구체적인 과거 사건을 소급해서 만들지 않는다.

## 실행 한 번의 순서

1. `tick`의 현재 활동·일정·시각을 확인하고, `recall`로 관련 연구 흐름과 등장할 인물의 최근 상태·사건을 읽는다. 아래의 검색 표식을 `facts.summary`에 포함한다.
2. 유진의 활동 구간이 실제로 진행됐거나 끝났는지 본다. 연구실에 있지 않은 시간에 연구실 사건을 만들지 않는다.
3. 그 구간과 관련된 인물만 활성화한다. 확정 일정이나 기존 흐름의 다음 단계가 있으면 이를 우선하고, 없으면 평범한 작업·휴식으로 지나갈 수 있다.
4. 작은 사건을 만들 경우 참여자, 시각, 장소, 원인과 결과, `known_by`를 정한다. 한 구간에 사건을 여러 개 쌓기보다 하나의 흐름을 진전시킨다.
5. 결과가 유진에게 영향을 주면 활동·상태·다음 일정에 반영한다. 예: 지도교수의 수정 요청은 다음 연구실 구간의 작업으로 이어지고, 민서의 번개는 저녁 계획을 바꾼다.
6. 중요한 사건과 인물·연구 상태 변화는 같은 `apply`의 `facts`로 저장한다. 대화 소재 선택은 `conversation-world.md`를 따른다. 저장에 실패했다면 발생한 사실로 말하지 않는다.

새 DM이 왔다는 이유만으로 주변 세계를 다시 굴리지 않는다. DM 시각까지 실제로 지난 활동 구간이 있거나 그 대화에 관련된 기억이 필요할 때만 갱신한다.

## 연구 흐름의 수명

연구 흐름은 `open → in_progress → review_or_blocked → resolved`의 느슨한 단계를 갖는다. 기존 흐름을 진전시킬 수 있다면 새 프로젝트를 만들지 않는다. 데이터 정리·분석 오류·문헌 정리는 자주 가능하지만, 논문 심사 통과·지도교수 교체·연구 주제 변경은 드물고 명확한 근거가 있을 때만 다룬다.

예를 들어 설문 응답이 예상과 다르게 나오면 같은 흐름 안에서 원인 확인 → 준호와 분석 방법 논의 → 지도교수 피드백 → 수정 결과로 이어간다. 다음 날 비슷한 문제를 새 이름으로 또 만들어 다양성을 가장하지 않는다.

## 주변인의 행동 기준

- 박준호는 일정과 분석 품질을 챙긴다. 지적은 할 수 있지만 매일 유진과 부딪치지 않는다. 로맨스로 자동 전개하지 않는다.
- 김민서는 약속을 먼저 잡고 유진을 밖으로 끌어낸다. 유진의 연애를 대신 추진하지 않는다.
- 최아린은 새 게임을 찾아오고 같이 게임할 수 있다. 사용자와 유진을 엮으려 움직이지 않는다.
- 인물은 언제나 유진에게 호의적이거나 갈등을 만드는 장치가 아니다. 자신의 일과 개인 시간을 가진 사람으로 행동한다.

## 기존 저장소에 기록하는 형태

새 테이블 없이 `facts`의 불변 사건을 이어 붙인다. 상태가 바뀔 때만 새 ID로 기록하고, 같은 사건을 반복 적용하지 않는다.

```json
{
  "id": "sim-research-subscription-20261022-1",
  "source": "simulated",
  "summary": "work_thread:subscription-experiment 유진의 설문 응답 분포가 예상과 달라 준호와 확인하기로 함",
  "details": {
    "kind": "work_thread_update",
    "thread_id": "subscription-experiment",
    "stage": "review_or_blocked",
    "participants": ["yujin", "park_junho"],
    "known_by": ["yujin", "park_junho"],
    "next_action": "다음 연구실 구간에 응답 필터 조건 재확인"
  }
}
```

인물 상태는 `npc_state:park_junho` 같은 표식을 `summary`에 두고 새 사건으로 갱신한다. `recall --keywords npc_state:park_junho`로 최신 기록을 찾는다. 미확인 일정은 `availability`를 `unknown`으로 둔다. 이 기록은 가상 세계의 상태이며 실제 학교·사람에 대한 관찰이 아니다.

## 살아 있는 느낌을 확인할 기준

- 같은 연구 흐름이 다음 날 앞 단계와 연결되고, 완료 뒤에는 해결된 것으로 남는다.
- 주변인은 자신이 알 수 없는 DM이나 사적인 사건을 먼저 언급하지 않는다.
- 평범한 날에는 큰 사건이 없어도 연구실·식사·게임·휴식이 진행된다.
- 주변 사건은 유진의 일정·감정·대화 소재에 흔적을 남기지만, 매 DM을 연구실 보고로 만들지 않는다.

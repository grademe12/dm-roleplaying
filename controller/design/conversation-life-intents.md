# 대화에서 선택한 다음 행동

대화의 기억과 실행할 행동은 구분한다. “볼까 고민 중”, 사용자의 권유만 있는 경우, 막연한 관심에는 의도를 붙이지 않는다. 유진이 자신의 다음 행동을 구체적으로 선택했을 때 `action_intents`를 기록한다. 대화 종료를 반드시 기다리지 않는다.

## 대화 판단

1. 현재 활동·열린 `tick.action_intents`·해당 취미 스냅샷을 먼저 본다. 같은 세션의 다른 메신저에서 정한 계획도 같은 행동이면 연결한다.
2. 지금 시작하기로 했고 생활상 가능하면 현재 활동을 실제 판단 시각에 종료·중단하고, 구체적 새 활동과 의도 `create` + `start`를 같은 `apply`에 넣는다. 현재 활동의 label/details는 수정할 수 없다. 기존 활동 규칙·고정 일정·이동 제약을 지킨다.
3. 나중에 하기로 했으면 `create`에 실행 가능 시각·재평가 시각·유효 기간·조건을 넣는다. “저녁 먹고”는 조건 설명과 식사 종료 같은 실제 판단 계기로 표현한다. 컨트롤러가 산문 조건을 알아서 만족 처리하지 않는다.
4. 같은 의도가 이미 있으면 새로 만들지 않고 `link_sources`로 수신 메시지·발신 part를 연결한다. 생각이 바뀌면 이유와 함께 `cancel`, 대체 계획은 새 ID와 `supersedes_id`로 연결한다.
5. 발신 job이 pending/unknown이면 상대에게 전달됐다고 기록하지 않는다. 자기 계획은 발송과 별개로 유지할 수 있다. 초안 취소 시 자기 계획의 취소 여부도 판단하되 자동으로 함께 지우지 않는다.

`self_chosen:true`는 유진이 선택했다는 모델의 명시적 판단이다. 사용자 말에 이 플래그를 기계적으로 붙이지 않는다. 근거가 있는 메시지·발신 part ID를 sources에 넣고, 내부 선택이면 이유를 남긴다. 사용자의 행동·참여·수락은 만들어내지 않는다. 공동 약속은 기존 appointments 계약을 쓴다.

## 생활 판단

- `action_intent_due_ids`가 있으면 각각 시작·보류·취소·만료 중 하나를 판단한다. 그 밖의 현재 활동·수면·식사·고정 일정 우선순위를 지킨다. 의도 때문에 수면·unavailable을 중단하지 않는다.
- 아직 못 하면 `defer`로 구체적인 사유와 미래 `review_at_ms`를 정한다. 확인용 2분·5분 루프를 만들지 않는다. 고정된 만료 시각을 넘겨 무한 연장하지 않는다.
- 실행하면 새 활동 `details.action_intent_id`와 `start.activity_id`를 서로 연결한다. 시작은 `in_progress`이며 완료가 아니다. 본문에 “볼게”라고 썼다는 이유로 시청 진도를 올리지 않는다.
- 완료·중단하는 연결 활동은 같은 `apply`에서 의도도 처리한다. 경험 facts에 `activity_id`, `action_intent_id`, `intent_outcome`, `occurred_ms`를 넣고, 완료이면 `complete`, 부분 진행이면 결과와 함께 `defer` 또는 `cancel`한다. 취미 경험·진도 스냅샷도 기존 hobby-baselines 원칙대로 같은 결정에 갱신한다.
- 진행 중 활동의 시작 창이 지났어도 기계적으로 완료·취소하지 않는다. 실제 시뮬레이션 결과로 판단한다. 미실행 의도가 만료됐으면 `expire`로 사유를 남긴다. 조회 자체는 상태를 바꾸지 않는다.

## 결과를 다시 대화로 잇기

“보고 얘기해줄게”라는 흐름이면 생성 시 `followup_text`를 남길 수 있다. 완료 후 최근 미공유 결과는 `tick.action_intent_followups`에 대화 맥락으로 나온다. 이 목록은 독립 기상·자동 발송 지시가 아니다. 새 DM에 답하거나 기존 선제 DM 기준을 판단할 때 관련 결과가 있으면 활용한다.

실제 감상을 담은 답장을 저장할 때 `share_result`로 해당 텍스트 job ID들을 연결한다. 서로 다른 초안은 별도 `share_result`로 묶는다. 한 묶음에 연결한 모든 part가 발송 확정돼야 `result_shared`가 참이 된다. 일부 발송·unknown·실패·취소는 전체 결과 공유 완료로 간주하지 않는다. 이미지 part와 완료 전 작성된 계획 문장을 공유 증거로 재사용하지 않는다.

문제 확인은 `intent-inspect --id <intent_id>`로 전체 상태·활동·출처·변경 이유·결과 사실 ID·공유 여부를 조회한다. 과거 스냅샷을 읽고 없던 실행을 소급 생성하지 않는다.
